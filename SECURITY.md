# Deck — модель безопасности и доверия

Deck — локальный персональный инструмент: веб-доска сессий Claude Code + рабочая консоль,
поднимающая встроенный HTTP-сервер и запускающая `claude` через Agent SDK. Ниже — что и как
защищено, и где осознанные компромиссы.

## Сетевая поверхность (локально)

- **Сервер слушает только loopback (`127.0.0.1`)**, не `0.0.0.0`. Из локальной сети (LAN) до
  Deck достучаться нельзя. URL приложения — `http://localhost:<порт>`.
- **Гейт Host/Origin**: запрос с чужим `Host` (защита от DNS-rebinding) или чужим `Origin`
  (кросс-ориджин вкладка браузера, в т.ч. `EventSource`) отклоняется (403).
- **Токен процесса для всех `/api/`**: сервер генерирует случайный токен на запуск и инжектит
  его в `<meta name="deck-token">` страницы. Прочитать HTML кросс-ориджин нельзя (SOP), поэтому
  токен доступен только самой странице Deck. Это закрывает CSRF без `Origin` (например
  `<img src="http://localhost:PORT/api/chat?...&prompt=...">` с произвольного сайта, который
  прежние слои пропустили бы: `Host` там localhost, `Origin` отсутствует).
- **Валидация имён MCP**: имя, уходящее в `claude mcp login/remove` (spawn с `shell:true` на
  Windows), ограничено `^[A-Za-z0-9._-]{1,64}$` — без инъекции в `cmd.exe`.
- Локальный процесс на той же машине, крафтящий запросы без `Origin` с `Host: localhost` и
  знающий токен из страницы, теоретически может дёрнуть API — но такой процесс уже имеет
  выполнение кода на машине, это не эскалация. Основные векторы (LAN, вкладка браузера) закрыты.

## Обновления

- **Сборки не подписаны**: сертификата подписи кода нет. Штатная проверка Authenticode
  (Windows) отключена — иначе неподписанная сборка не установилась бы.
- **Целостность держится на sha512** из `latest.yml`, который electron-updater читает из
  GitHub-релиза по HTTPS. Подмена файла без совпадающего хэша не установится.
- **Остаточный риск**: компрометация GitHub-аккаунта/токена с правом публиковать релизы
  (подпись бы это дополнительно закрыла — её нет). Поэтому:
  - **автоскачивание выключено** — загрузка только по явной кнопке «Обновить»;
  - **автоустановка при выходе выключена** (`autoInstallOnAppQuit = false`) — установка только
    по явной кнопке «Перезапустить и установить», ничего не ставится молча.
- Если появится сертификат подписи — вернуть `verifyUpdateCodeSignature` (убрать заглушку в
  `electron/main.cjs`) и подписывать nsis-таргет; это восстановит нативную проверку.

## Секреты

- Токены Jira/TeamCity/GitLab шифруются через Electron `safeStorage` (`userData/<svc>-token.bin`).
  В standalone-режиме (без Electron) — только через `.env` (безопасно сохранить нельзя).
- Токены **не отдаются наружу** через API (только флаг `tokenSet`) и не пишутся в логи.
- `.env` и `*-token.bin` — в `.gitignore`.

## Данные и целостность работы

- Сторы Deck (`deck-config/projects/tags/names/runs.json`) пишутся **атомарно** (temp + rename) —
  краш/гонка в момент записи не оставит усечённый файл.
- Один писатель на сессию (single-writer по `session_id`): второй `--resume` в тот же `.jsonl`
  не запускается (перенаправляется в steering живого хода), чтобы не портить транскрипт.
- Файлы сессий читаются только из папки проектов; просмотрщик файлов — только в пределах `cwd`
  сессии (traversal-гарды).
