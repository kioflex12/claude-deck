# Claude Deck

Локальное десктоп-приложение для управления **контекстами Claude Code** — доска сессий и рабочая консоль в одном окне, замена возне с терминалом и VSCode-расширением.

**Карточка = сессия Claude.** Видно статус в Jira, ветку, MR, статусы сборок Android/iOS и заполненность окна контекста. По клику — полноэкранная сессия: слева живой чат, справа панель с описанием, ветками, MR и сборками. Несколько сессий можно держать рядом в **воркспейсе** — сплит-лейаут как в VS Code.

## Возможности

- **Доска сессий** — колонки по стадии dev-workflow и статусу Jira; каждый элемент кликабелен в исходную систему (ветка → GitLab, MR → страница MR, сборка → TeamCity, задача → Jira).
- **Воркспейс** — несколько живых сессий одновременно в сплитах (лево/право/верх/низ), таб-группы, докинг перетаскиванием вкладок; лейаут переживает перезапуск.
- **Живой чат** через Claude Agent SDK — стрим, thinking, счётчик токенов, аппрувы Edit/Write/Bash, режимы разрешений, вложение любых файлов (скриншоты — инлайном, дампы/логи — путём для чтения).
- **Режимы создания контекста** — Обычный, Bugfix и Dev-workflow: последние два собирают первый промт из полей (задача, окружение, копия клиента) и сразу запускают нужный скилл.
- **Скиллы и MCP** — вкладки с реальными `.claude/skills/*` и MCP-серверами текущего окружения, поиск, вставка `/команд`.
- **Интеграции** — живой статус Jira, MR из GitLab, сборки из TeamCity, индикатор лимитов аккаунта Claude, лента «Требует внимания» (блокеры, упавшие сборки, незакоммиченные копии).
- **Настройка почти не нужна** — папка сессий Claude определяется сама, токены интеграций подтягиваются автоматически; приветственный экран при первом запуске.
- **Как настоящее приложение** — трей, сворачивание, командная палитра (Ctrl/⌘+K), автообновление из GitHub Releases.

## Требования

- Установленный и **залогиненный Claude Code** на этой машине — Deck запускает `claude` через Agent SDK и использует его OAuth (отдельный ключ не нужен).
- Для запуска из исходников — **Node.js 20+**.

## Запуск

- **Приложение (основной путь):** установить из инсталлятора `Deck Setup <version>.exe` (собирается CI по тегу) — дальше обновляется само. Из исходников: `npm install && npm run app`.
- **Standalone веб-сервер (без Electron):** `npm start` (или `node server/server.mjs`; либо лаунчеры `scripts/start-deck.bat` / `scripts/start-deck.sh`) → браузер на `http://localhost:4317`.

Правки серверного кода требуют перезапуска, `index.html` и `web/` — просто F5.

## Настройка

Всё живёт в экране **Настройки** (⚙ в топбаре) и хранится в `deck-config.json` (в приложении — в `userData`; токены Jira/TeamCity/GitLab шифруются хранилищем ОС). В типичном случае настраивать ничего не нужно:

- **Папка сессий** — по умолчанию `~/.claude/projects`, определяется автоматически.
- **Jira / TeamCity / GitLab** — необязательны; токены подтягиваются из окружения, хосты задаются в ⚙. Без них соответствующие данные просто не показываются.

Значения можно задать и через `.env` в корне репо (для standalone). Приоритет: настройки → env/`.env` → дефолт.

## Структура

```
server/     — бэкенд: zero-dep Node-сервер (server.mjs) + домены (core/sessions/chat/sdk/services/auth/skills-mcp/unity/text)
web/        — фронтенд: ES-модули UI (доска, сессия, воркспейс, композер, рейл, палитра…)
electron/   — нативная оболочка (main.cjs поднимает сервер и грузит его в окно; трей, автообновление)
index.html  — тонкий HTML-шаблон приложения
test/       — тесты (node:test, zero-dep)
scripts/    — лаунчеры standalone-сервера
```

Сервер читает реальные сессии из `~/.claude/projects/*/*.jsonl`, состояния `dev-workflow/WO-*.json`, ходит в Jira/TeamCity/GitLab и гоняет Claude через `@anthropic-ai/claude-agent-sdk`. Тот же серверный код работает и как отдельный веб-сервер — Electron лишь оборачивает его в нативное окно.

## Безопасность

Сервер слушает только loopback, за токен-гейтом и защитой от DNS-rebinding / кросс-ориджин. Подробно — [SECURITY.md](SECURITY.md).
