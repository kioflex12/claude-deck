# Claude Deck

Локальное **десктоп-приложение** для управления **контекстами Claude Code** — замена неудобному VSCode-расширению.

Канбан-доска, где **карточка = контекст (сессия Claude)**: статус в Jira, ветка, MR, статусы сборок Android/iOS, окно контекста. По клику — **полноэкранная сессия**: слева живой чат (стрим, thinking, токены, аппрув Edit/Write/Bash, режимы разрешений, вложения-скриншоты), справа рейл (описание, ветки, MR, сборки, заметки). Плюс вкладки **Скиллы** и **MCP**, командная палитра (Ctrl K), индикатор аккаунт-лимитов Claude.

## Зачем своё, а не готовое

Похожие инструменты (Nimbalyst, langwatch/kanban-code, code-factory) завязаны на **GitHub PR + git worktree**. Наш конвейер другой: **GitLab MR + Jira + TeamCity + файлы `dev-workflow/WO-XXXX.json` + копии `client-unity`**. Этот «клей» и есть смысл проекта — ни один готовый тул его не покрывает.

## Архитектура

Десктоп-приложение на **Electron** поверх **zero-dep Node-сервера + статического HTML**. Тот же серверный код работает и как отдельный веб-сервер (`node server.mjs` → браузер) — Electron лишь оборачивает его в нативное окно с треем, автозапуском и автообновлением:

- **`server.mjs`** — HTTP-сервер (свободный порт; `4317` в standalone) на голом `node:http`. Читает реальные сессии из `~/.claude/projects/*/*.jsonl`, состояния `dev-workflow/WO-*.json`, ходит в TeamCity/GitLab/Jira, гоняет живого Claude через **Agent SDK** (`@anthropic-ai/claude-agent-sdk`, существующий OAuth-логин Claude Code — без отдельного ключа).
- **`index.html`** — весь UI одним файлом (дизайн из `prototype/index.html`).
- **`electron/`** — нативная оболочка (`main.cjs` поднимает сервер и грузит его в окно; трей, сворачивание в трей, автозапуск, автообновление из приватных GitHub Releases).

## Запуск

**Требования:** установленный, **залогиненный Claude Code** на этой машине (real-Claude, usage-лимиты и создание сессий работают через его OAuth). Для запуска из исходников — Node.js 20+.

- **Десктоп-приложение (основной путь):** установить из инсталлятора (`Deck Setup <version>.exe`, собирается CI по тегу) или запустить из исходников — `npm install && npm run app`. Настройки (папки, Jira) — кнопка ⚙ в топбаре; вход в Claude — прямо из окна.
- **Standalone веб-сервер (без Electron):** `node server.mjs` (или лаунчеры — двойной клик `start-deck.bat` на Windows / `bash start-deck.sh` на macOS/Linux) → браузер на `http://localhost:4317`.

Правки `server.mjs` требуют перезапуска, `index.html` — просто F5.

**Автозапуск после перезагрузки (Windows, опц.):** положи ярлык на `start-deck.bat` в папку автозагрузки — `Win+R` → `shell:startup`.

### Переменные окружения (опционально)

Всё это настраивается через экран **Настройки** (⚙ в топбаре) и хранится в `deck-config.json` (в приложении — в `userData`; Jira-токен шифруется хранилищем ОС). Значения также можно задать через `.env` в корне репо (gitignored) — удобно для standalone-режима. Приоритет: настройки → env/`.env` → дефолт.

- `JIRA_HOST`, `JIRA_EMAIL`, `JIRA_TOKEN` — живой статус Jira на карточках. Без них Jira-колонка молча берётся из локального `dev-workflow`.
- `WO_STATES_DIR` — путь к `dev-workflow/workflow-states`. По умолчанию **пусто** — задай в Настройках (или env), иначе колонка «Статусы» мягко деградирует (доска заполнится по активности сессий).
- `CLAUDE_PROJECTS_DIR` — где лежат транскрипты (по умолчанию `~/.claude/projects`).
