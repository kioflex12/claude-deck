# Deck — бэклог

## Цель: уйти от концепта → десктоп-приложение (Electron) — ✅ ДОСТИГНУТА

Решено 2026-07-27: паковать Deck в настоящее десктоп-приложение на **Electron** (не Tauri —
бэкенд `server.mjs` + Agent SDK это Node, а Electron-main и есть Node, переиспользуется как
есть; Tauri потребовал бы Node-сайдкар). Своя тонкая оболочка, без чужих trust/consent-гейтов.

Итог 2026-08-03: приложение собрано и раздаётся, автообновление работает end-to-end
(GitHub Releases → electron-updater), пользователь обновляется на лету.

**Зависимость (неустранимая):** на машине всё равно нужен установленный и залогиненный
Claude Code CLI — SDK шеллит его и берёт OAuth из `~/.claude`. Electron бандлит Node, но не `claude`.

### DESKTOP-1 — MVP-оболочка ✅ СДЕЛАНО
`electron/main.cjs` поднимает `server.mjs` на свободном localhost-порту, открывает `BrowserWindow`.
Иконка, своё окно, `electron-builder` → NSIS-инсталлятор под Windows. Agent SDK в Electron-main работает.

### DESKTOP-2 — как настоящее приложение ✅ СДЕЛАНО
Трей-иконка, single-instance lock, нативное меню, нативные уведомления (мост в клиент → `openSession`),
командная палитра через нативный аксельратор.

### DESKTOP-3 — дистрибуция ✅ СДЕЛАНО (Win); macOS-подпись отложена
NSIS-установщик, версия + автообновление, обход Authenticode для неподписанной сборки
(`verifyUpdateCodeSignature`, целостность держит sha512 из latest.yml). Подпись/нотаризация macOS —
не делаем (Win-раздача самодостаточна; mac-таргет собирается, но неподписанный).

### TECH-3 — Перф `/api/sessions` ✅ СДЕЛАНО

### TECH-4 — Надёжность 🔶 В РАБОТЕ (2026-08-03)
Сделано в этот заход:
- **Ретраи/бэкофф** на транзиентных сбоях (сеть/timeout/429/5xx) — общий `fetchRetry` в `core.mjs`,
  подключён к TeamCity/GitLab/Jira. Корень пустой «Заблокировано» был именно транзиентный 503 Jira.
- **Падения интеграций видимы, а не проглочены** — серверный трекинг здоровья (`/api/health`) +
  топбар-индикатор деградации (какой сервис + причина); в рейле причина сбоя уже показывалась в секциях.

Осознанно НЕ трогаем: «тихие» `catch {}` на чтении файлов/парсинге `.jsonl`/записи в закрытый SSE —
это **намеренная деградация** (нет файла → пустой дефолт, битая строка → skip), не проглатывание ошибок
интеграций. Расширять их в шумные логи смысла нет.

Data-flow вычищен ранее в этой сессии: детект клиентской копии/ветки переведён на структурные поля `.jsonl`
(было — эвристика по частоте упоминаний), ключ MR-кэша = пара (ветка, wo) вместо гонки по одной ветке.
