# Deck — аудит стабильности (что доработать до системы, на которую можно положиться)

Дата: 2026-08-04. Метод: 3 независимых аудита кода (надёжность/наблюдаемость, архитектура/тесты, корректность данных/интеграции), read-only, каждый с `file:line`. Ниже — сведённый приоритезированный план.

## Вердикт

Deck **продуман сильнее типичного внутреннего инструмента** и уже крепок на «горячем» пути — открытая сессия перед глазами. Но **полагаться на него в unattended-режиме (fire-and-forget) пока рано**, и слабости **локальны, не архитектурны** (переписывать ничего не надо). Все три аудита сходятся: проблема концентрируется там, где **исполнение (фон) расходится с наблюдением (перезаход/уход с экрана)**, плюс открытая сетевая поверхность и отсутствие тестов у самого рискового кода.

Что уже сделано КРЕПКО (не трогаем): деградация интеграций видна (`markHealth`→`/api/health`), `fetchRetry` с бэкоффом, шифрование токенов (`safeStorage`), `.env`/токены не в git и не в логах, traversal-гарды (`resolveSessionPath`/`serveWeb`), безопасный спавн git (execFile массивом), `_summaryCache` по mtime с прунингом, steering в живой ход, ре-сёрфейс висящих вопросов/аппрувов после обрыва SSE, фоновое дорабатывание при закрытии вкладки, single-instance lock, OS-ветвление для Unity.

## 🔴 Tier 1 — критично (безопасность + потеря работы). Без этого нельзя «доверять systemе».

### S1. Сервер открыт в сеть без auth → RCE-поверхность
`server.mjs:140` слушает все интерфейсы (нет host-аргумента → `0.0.0.0`/`::`), ни один роут не гейтит по Origin/Host/токену. `/api/chat` — это **GET** (EventSource) с `mode=bypassPermissions` и произвольным `cwd`. Любая вкладка браузера (cross-origin GET, спавн срабатывает независимо от читаемости ответа) или машина в LAN (DNS-rebinding) может запустить Claude с байпасом в выбранной папке = **выполнение кода на хосте**. `/api/file` с произвольным `cwd` (`sessions.mjs:582`) читает любые файлы.
→ Биндить `127.0.0.1`; проверять `Host`/`Origin` (только localhost); для мутирующих — токен из `loadURL`.

### S2. Автообновление без проверки подписи + тихая установка
`electron/main.cjs:322` `verifyUpdateCodeSignature=()=>null` + `oneClick` + `autoInstallOnAppQuit`. Целостность держится только на sha512 из публичного репо. Подмена релиза/`latest.yml` или компрометация токена → вредоносная сборка ставится без спроса. Крупнейший trust-gap vs подписанное расширение.
→ Подписать сборки (даже дешёвый серт вернёт нативную проверку) ИЛИ гейтить установку явным подтверждением + задокументировать sha512-модель.

### S3. Command injection на Windows через имя MCP
`skills-mcp.mjs:209,227` спавнят `claude mcp login/remove <name>` с `shell:true`, `name` — сырой query-параметр. `name` с `& | " %..%` вырывается в `cmd.exe`.
→ Валидировать `^[A-Za-z0-9._-]+$` или убрать `shell:true`.

### R1. Терминальные/фоновые сбои проглатываются без следа
`chat.mjs:290-297` — ошибка в `catch` уходит только `if(!closed)`; ни `catch`, ни `finally`, ни `done` не пишут `dbgLog` (он только на START/CLOSE). Если ход упал при закрытом канале (истёк auth, краш SDK) — на доске гаснет `serverActive` → «завершено», хотя ход **упал**. Это и есть «остановилось, непонятно что».
→ `dbgLog` на КАЖДОМ терминальном пути (subtype/is_error/message) независимо от `closed`; персистить причину для reentry.

### R2. Рестарт Electron бесследно теряет живые фоновые ходы
Всё состояние ходов только в памяти (`core.mjs:135-141`). Рестарт → Maps пусты, подпроцессы гибнут, `.jsonl` обрывается; `transcript.js:91` tail не стартует (нет ни `active`, ни `serverActive`) → просто оборванный транскрипт без объяснения.
→ На старте сервера помечать осиротевшие ходы видимым маркером; рассмотреть персист in-flight состояния.

### R3. Нет single-writer guard → двойной `resume` → порча `.jsonl`
На перезаходе в активную сессию `serverBusy` ещё `false` (до первого `tailTick`), композер активен → новый промт (`composer.js:331`) запускает второй `EventSource` с `resume` **при живом фоновом ходе**. Сервер допускает несколько `activeStreams` с одним `key` (`chat.mjs:158`). Два `--resume` пишут в один файл → задвоение/порча. Тот же риск — fallback `steerPrompt→runPrompt`.
→ Серверный single-writer по `session_id` (второй resume при живом ходе — отклонять/переводить в steer); на клиенте гейтить send до первого ответа tail.

### D1. Неатомарная запись сторов → тихая потеря имён/тегов/конфига
`deck-names/tags/config.json` пишутся прямым `writeFileSync` без temp+rename (`sessions.mjs:36,58,619`, `core.mjs:56,66`). Краш/гонка в момент записи → усечённый файл → при загрузке `catch→{}` → молча теряется весь стор. `movePath` (атомарный rename) в репо есть, но здесь не применён. `setTags/setName` глотают ошибку записи, а вызывающий рапортует успех.
→ Писать в temp + `renameSync`; пробрасывать ошибку записи (реальный код статуса).

## 🟠 Tier 2 — важно (наблюдаемость, корректность, кросс-платформа)

### R4. Фоновое ожидание аппрува/вопроса невидимо и бесконечно
`notifyInput` дёргается только из ОТКРЫТОЙ сессии; `pollSessions` не опрашивает `/api/pending-*` для не-открытых. На доске «работает» и «ждёт ответа» не различимы. На сервере у зависшего на `canUseTool`/hook хода нет таймаута/GC. Fire-and-forget: ушёл, ход упёрся в аппрув Bash → ждёт часами без сигнала.
→ Board-опрос pending для активных сессий + `notifyInput` + отдельный статус «ждёт ответа»; серверный лимит на залипшие ожидания.

### R5. При перезаходе не видно причину финиша (лимит/ошибка) и нет «Продолжить»
Кнопка «Продолжить» и нота рисуются только из живого SSE-`done` (0.1.59). `buildSessionBlocks` не рендерит `result`/`error_max_turns`/`is_error`. Фоновый ход, добивший `maxTurns` или упавший при закрытом канале, при reentry — оборванный транскрипт без причины.
→ На reentry читать последний `result` из `.jsonl`, показывать причину + «Продолжить».

### R6. Утечка heartbeat-таймера на ранних отказах `apiChat`
`setInterval` (`chat.mjs:108`) до навешивания `req.on('close')` (`:163`); ранние `return fail(...)` (`:116/134/139/144…`) минуют cleanup → интервал живёт вечно, пишет в закрытый `res`.
→ `clearInterval(heartbeat)` в `fail()`.

### D2. MR создаётся в ЧУЖОМ проекте
`services.mjs:255-260` `glFindProject` при отсутствии точного совпадения возвращает `list[0]`; `apiCreateMr` не отсекает (бросает только на `null`). `repoHint="client-unity"` матчит зеркала/форки → MR в неверный репозиторий (необратимо).
→ Возвращать `null`, если нет точного совпадения `path`/`name`.

### D3. WO-префиксная коллизия сборок/MR
`services.mjs:88` (`indexOf(wo)===0`) и `:180` (`search=<wo>`) — `WO-123` матчит `WO-1234-foo`. Задаче приписывается чужая сборка/MR → колонка «Build In Progress» и «Сборка упала» врут.
→ Матчить `wo + '-'` / границу слова (как `detectBranchFromText`).

### D4. `fetchRetry` повторяет неидемпотентные POST → дубли
Ретрай на 5xx/429/timeout для `jira-comment`/`create-mr`/`trigger-build` (`services.mjs:243/270/288`). Если запрос уже прошёл, а шлюз вернул 502 — второй коммент/MR/сборка.
→ `retries:0` для этих POST или идемпотентный ключ.

### D5. Хрупкость парсинга: глобальный regex по всему 38МБ-файлу
`text.mjs:8-25` матчит `"key":"..."` в любом месте, включая процитированный транскрипт внутри `tool_result` (экранированная `\"aiTitle\":\"` тоже совпадает). Затрагивает title/model/lastPrompt/cwd. `cwd` питает git-dirty и base `/api/file` → потенциально опасно.
→ Per-line JSON (первая/последняя запись нужного типа), не глобальный regex.

### X1. macOS: голый `claude` не резолвится в упакованном app
`core.mjs:155` `CLAUDE_BIN='claude'`, прямой спавн в `auth.mjs:129/191/243` и `skills-mcp.mjs`. Finder-Electron имеет усечённый PATH (нет `/opt/homebrew/bin`) → `ENOENT`. Только `sdk.mjs:35` пытается резолвить (и тоже наследует куцый PATH).
→ Единый резолвер `claude` с абсолютным фолбэком, через который идут ВСЕ спавны.

### T1. Нет поведенческих тестов у самого рискового кода
`dom-stub.mjs:52` стабит `EventSource` no-op → в `stream.test` `es.onmessage/onerror` не срабатывают: ветки `text/thinking/tool/approval/question/turn/done/error`, `finish()`, tail-fallback — не тестируются. Серверный `apiChat` (цикл, `canUseTool`-ветки, хуки, steering, closed-continuation) — без теста (`getSdkQuery` спавнит реальный claude, нет seam). `package.json:11` — ручной список файлов, не glob → новый тест молча не запускается.
→ Инъекционные seam для `EventSource` и `getSdkQuery`; тесты event-цикла и permission-гейтинга; glob в "test".

## 🟡 Tier 3 — долг/косметика

- **A1.** `app.js` — точка входа И хаб общих хелперов (`aReal/jiraUrl/isBaseBranch/UI_BUILD`) внутри большого цикла импортов; хелперы определены ПОСЛЕ импортов → TDZ-риск, если кто-то вызовет на module-eval. → вынести в dep-free `consts.js`/`util.js`.
- **A2.** Один мутабельный `S` с ~11 таймер-хэндлами, инвариант стрима переопределён в 4 местах (`stopStream`/`finish`/`onerror`/`userStop`). → инкапсулировать lifecycle стрима в объект с единым `teardown()`.
- **A3.** Три функции по 170–230 строк (`runPrompt`, `apiChat`, `openSettingsModal`) — вся сложность в нетестируемом коде. → разбить на именованные хендлеры (заодно даёт seam для T1).
- **C1.** git-dirty `maxBuffer:4MB` (`sessions.mjs:372`) → репо с большим untracked превышает → `resolve(null)` → репо ТИХО пропадает из ленты. → поднять/убрать лимит.
- **C2.** Ключи кэшей по сырому `cwd` — регистр буквы диска (`sessionCwds`, `_gitCache`) → двойной git + две строки одного репо. → нормализовать регистр/разделители.
- **C3.** Login-watcher leak: 180с-таймаут не убивает child/не чистит `activeLoginId` → все будущие логины реюзают мёртвую запись (`auth.mjs:167-173`).
- **C4.** `SKILLS_CACHE` без TTL/сброса (`skills-mcp.mjs:15`) → новый скилл невидим до рестарта, растёт.
- **C5.** `sendJSON` split-brain: quick-actions отдают 200+`{ok:false}`, config/tags/name — 400. → единая конвенция.
- **C6.** Копипаст, который разъедется: scope/branch-резолв (`sessions.mjs:304` vs `:495`), token-sum (`lastUsageIn` vs `lastUsageWindow`), `DEV_BUILD_TYPES` vs `TC_BUILD_TYPES`.
- **C7.** `effectiveColumn` — `buildActive` перекрывает `done`/`blocked` (`columns.js:35`).
- **C8.** `deck:openPath` открывает любой путь дефолтным приложением ОС без allowlist (`main.cjs:190`).
- **C9.** Прочее: `deck-debug.log` без ротации; `pendingQuestions` может утечь, если SDK-hook прошёл по таймауту; ложный «готово»-пинг в зазоре steering-очереди; reentry-фейл при транзиентной ошибке `/api/session`; delete-session не чистит имя; `_tags/_names` мемоизируются навсегда; `pingEnv` мягкий SSRF.

## Рекомендованный порядок

1. **Наблюдаемость фона + видимый терминал** (R1, R2, R5) — прямо закрывает «остановилось, непонятно что». Дёшево-средне.
2. **Целостность работы** (R3 single-writer, D1 атомарная запись) — чтобы не терять/не портить. Средне.
3. **Сетевая безопасность** (S1 localhost-бинд+Origin, S3 инъекция) — S1 дёшево (host-аргумент+Origin-чек), большой выигрыш.
4. **Корректность интеграций** (D2, D3, D4) — точечно, дёшево.
5. **Тестовые seam + разбивка** (T1, A2, A3) — фундамент, чтобы регрессии этого класса ловились. Крупно.
6. **Кросс-платформа** (X1) — перед macOS-раздачей.
7. Trust-путь обновления (S2) — когда дойдут руки до подписи.
8. Tier 3 — по мере.
